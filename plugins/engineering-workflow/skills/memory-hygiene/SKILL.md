# Keep durable guidance accurate

Read the current repository instructions and relevant live source before changing
persistent guidance. Preserve decisions, their reasons, user preferences and
non-obvious constraints; avoid copying facts that are obvious from the code.

- Keep project architecture, verification commands and domain invariants in the
  project. Keep reusable procedures in their central skill source.
- Replace superseded guidance rather than appending contradictory amendments.
  Check callers and links before moving or deleting an instruction file.
- Verify volatile facts (paths, commands, delivery status) against live evidence
  before relying on them. Distinguish historical records from current rules.
- Write concise skill descriptions that identify the triggering situation. Read
  the full skill before using it; its description is not the procedure.
- Preserve the user's scope and existing authorization. A local workaround is
  not automatically a rule for every future task or repository.
- When editing shared guidance, inspect at least one consuming repository for
  incompatible assumptions. Never edit installed caches as the maintained source.
